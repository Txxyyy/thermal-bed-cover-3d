# 温控床笠 3D 性能优化记录

日期：2026-10-28。目标是在保持现有模型、冷暖光效、阴影、像素倍率和正常刷新节奏的前提下，减少重复工作。以下数据来自本机桌面 Chrome 和 Node，不是手机发热或耗电实测。此轮对比在深浅主题适配之前完成；当前嵌入页面的背景合成和取景已调整，目标手机上的表现需重新测量。

## 修改内容

- 静止的灯光和投影物复用已有阴影图；主机独立视角切换、水路显示或隐藏等改变投影物可见性的操作会刷新阴影图。相机移动和冷暖流光本身不重新生成静态阴影。
- 关闭织物光效且水路未显示、没有其他可见动画时，画面稳定后停止绘制；打开光效、切换视角或显示水路后恢复。水路开启时，粒子仍按原样运动。
- 织物纹理生成时直接写入像素，避免为每个像素分配临时数组；水路场预先计算网格坐标，避免内层重复计算。纹理分辨率、曲线和实际生成数据保持一致。
- Flutter 离线资源已重新导出；现有隐藏页面、暂停、左右独立温控和恢复机制保留。

## 同机对比

对比在相同的 780×840 桌面 Chrome 窗口中进行，使用固定双区状态与暂停相位。`renderer.info.render` 的数据是一次画面渲染的统计，包含阴影通道，不是唯一模型面数、GPU 耗时或手机功耗。

| 场景与指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 稳定整体视角，每帧绘制调用 | 114 | 60 |
| 稳定整体视角，每帧渲染三角形 | 258,474 | 129,708 |
| 关闭光效且无其他可见动画，800 ms 内绘制帧数 | 49 | 0 |
| 重新打开光效后的 800 ms 内绘制帧数 | — | 49 |

在该测试场景下，稳定帧的绘制调用约减少 47%，渲染三角形约减少 50%；原因是静态阴影不再随每帧重复绘制。活动光效仍由浏览器按原有 `requestAnimationFrame` 调度，不设置新的帧率上限。

首次生成数据的局部耗时：2048×2048 绗缝纹理在桌面 Chrome 的三次运行中位数由 357.2 ms 降至 196.2 ms；水路场在同一台电脑的 Node 中预热后交替各运行五次，中位数由 35.2 ms 降至 26.9 ms。这只是局部函数的同机观察，不能代表 APP 总启动时间或手机耗电。

优化前后绗缝纹理、普通与深色织物纹理，以及实际水路场的数据 SHA-256 一致。整体、面料、主机、水路及返回整体的固定画面逐像素比较：除面料细节的 655,200 个像素中有 3 个像素最大相差 1 个颜色级别外，其余像素一致。Chrome 中使用 iPhone user-agent 触发的手动阴影分支，四个对应画面像素一致；这不是 iOS 原生 WebView 或 iPhone 真机测试。

原始对比图、采样数据与哈希见 `output/perf-qa/`；行为测试记录见 `output/qa/checks.json`、`output/qa-mobile/checks.json` 和 `output/qa-embed/checks.json`。

## 真机验证边界

本轮未检测到连接的手机，也未在原生 iOS/Android WebView 上运行新资源。尚无实际 GPU 时间、电池消耗、机身温升、长时间帧率和低端机数据。建议在至少一台 iPhone 和一台目标 Android 设备上，以相同亮度、环境和电池状态对比：双区动态光效、暂停画面、隐藏页面，以及不加载 3D 的基线。记录首次显示时间、帧率与卡顿、CPU/GPU、内存、电量和机身温度，再决定是否还有优化空间。

集成时确保非当前 Tab / Offstage 传入 `visible: false`；路由覆盖使用 `routeObserver`。错误的可见性状态会导致本应隐藏的 3D 页面继续运行。
